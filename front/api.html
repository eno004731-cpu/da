Что важно

Ключевые наблюдения по архитектуре

Это уже не просто UI-таблица, а подсказка, как развивать backend без хаоса.

1. Локально auth уже отделён от backend заявок

Это важный архитектурный шаг: фронт уже умеет жить с отдельным auth-service, а orders backend можно подключить позже, не ломая login/reload/logout сценарии.

2. Orders API должен включаться только явно

Сейчас это контролируется runtime-флагами. Такой подход лучше, чем молча падать на `401/404` и выглядеть так, будто пользователь внезапно разлогинился.

3. Feature flag'и уже часть пользовательского контракта

Google login, удаление аккаунта и реальные операции с заказами не должны отображаться как рабочие, если backend их пока не реализует.

4. Эта страница может стать твоей мини-спецификацией

Когда будешь добавлять новый endpoint, обновляй таблицу вместе с кодом. Так проще держать frontend, backend и БД в одной картине.
